# Program illustration concept and parts plan

Ten focused Anatomy Figures, each with 40–80 fitted solid parts. The program's subject, practice and possible project are HTML outside the drawing. The initial SVG is server-rendered; all interaction is optional. The existing retrieval hero is an additional figure, not one of the ten programs.

Colors follow the requested roles, with independently authored light/dark four-tone materials. Neutral supporting feet and fasteners retain the publication's navy/ivory styling. Shape, location, visible controls and explanatory text reinforce color. Exact captions, authored states and pure example models live in `src/data/program-explainers.ts`.

Every mechanism rests on a common fourteen-part supporting base: four pads, four foot risers, one grooved bench, four corner fasteners and an engraved plate. The repeated base is supporting furniture; the ten subjects and controls are different. There are no decorative duplicate terminal screens on the rack, robot, navigation board, accelerator or service enclosure.

Geometry is generated by `scripts/anatomy/build.mjs` and `program-builders.mjs` using the unmodified MIT Anatomy kit. The generated manifest is the final named inventory. Robot, navigation and access-gate replay assets contain precomputed SVG fragments and the exact audited painter order at each sampled pose. They are fetched only when used; a failed fetch leaves the static explanation intact.

Validation: build and motion audits must report zero problems; line-end checks run in both themes; external SVGs must decode; live SVGs must contain the expected fitted parts. Browser QA checks every state, keyboard/touch, reset, offscreen suspension, reduced motion, no-JavaScript reading, theme contrast, row alignment, local navigation and configured public destinations. Review the 1× page captures and 4× figure captures under `artifacts/anatomy/`.
